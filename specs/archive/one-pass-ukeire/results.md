## 性能方法与结果

基线 `dc6ff5c`；候选为 `e0ba2d9` 加本次实现（归档清理前）。环境为 Windows 10 build
19045、Ryzen 7 3700X、`x86_64-pc-windows-msvc`、rustc/Cargo 1.98.0、LLVM 22.1.8，
默认 release profile，无自定义 Rust flags/CPU affinity。先分别构建并保存二进制再直接运行，
构建、测试、插桩、轨迹和计时全部串行。后续仅删除未使用的 test-only 访问器、修正文档，
不改测量时的 release 算法，也未重跑正式性能实验。

工作负载 `heuristic-benchmark-v1`，`games=2000,warmup=20`，起始 seed 7、10007。
先各做 3 对 B/B 校准；仅 seed 10007 有 1 对绝对差超过 2%（total 2.8422%、policy 2.8199%），
未触发事先约定的“同 seed 至少 2 对达到 2% 才阻塞”规则。这不证明能统计检出任意 2% 收益。
锁定配置后各运行五对 **B→C、C→B、B→C、C→B、B→C**，共 20 次正式进程，无剔除或补跑。
按每对 `1 - candidate_time / baseline_time` 取五个降幅的中位数：

## 成本与复测

64 个完整局的隔离插桩计数（不含续局）：距离调用 123106→15646，花色 DP 构建
91435→32270（21181 plain + 11089 mask），ukeire 均 6407 次。mask 状态、并列 OR 与
独立缓存增加了成本；120 个合成输入的插桩微测中，纯距离 cold/warm 中位成本反而增加
约 1.3%/4.8%，ukeire 成本比为 0.2109/0.0563。微测不是端到端门槛或显著性检验，
没有 allocator/峰值内存或后续函数采样，不能据此精确归因或认定下一瓶颈。

复测可在两个独立 checkout 执行 `cargo build --release --example heuristic_bench`，
保存二进制后串行交错运行 `heuristic_bench --games 2000 --seed 7 --warmup 20` 及
seed 10007 的同参数命令。须重新采集样本与行为轨迹；不能恢复已删除数据或保证重现数值。
