# Bounded exact Needed-mask DP（历史实验合同，2026-11-06）

研究能否用已知精确最优距离减少 `suit_table_masked` 的状态扩展和转移，并提高启发式
策略端到端效率。**这是允许停止或回滚的实验，不要求留下优化**；先证明正确，再测
计算量，最后验证真实速度，转移减少不等于加速。

**结论：保留最小 Needed cutoff，Change 已归档。** 最终验证摘要、本机测量与限制见
[results.md](results.md)。下文保留事前合同供追溯，它属于一次性实验，**不是长期
流程或每次改动须重做的清单**。

## 1. 边界

起点 `main@2d735b78dc46622fdddbcd7c1bd85285d21cd2a8`。不得改变规则、策略排序与
碰杠门控、精度、公开 API、信息边界或 checkpoint 语义。缓存仍限于原 evaluator
生命周期及副露／缺门／容量上下文；普通 `deficit()` 和 Surplus-mask 路径不得承担
额外计算、缓存查询或分配。首个候选仅优化 Needed-mask，保持现有状态、转移顺序和
mask 合并规则，不捆绑状态压缩、双 mask、位宽调整或预计算表。复用已有测试和
benchmark，不建设通用研究框架。

## 2. 精确性合同

上下文 `C` 固定副露、缺门及物理容量，沿用现有合法目标集合 `T_C`：

\[
D_C(H)=\min_{T\in T_C}\sum_t\max(0,T_t-H_t),\qquad
M_C(H)=\bigcup_{T:\,cost_H(T)=D_C(H)}\{t:T_t>H_t\}.
\]

`M` 是全部最优目标的 Needed-mask 并集。已知同一 `(H,C)` 的精确有限值 `d=D_C(H)`
时，只有累计代价严格 `g>d` 的路径可剪；**不能剪掉 `g=d`**，它仍可能零代价完成并
贡献独有 mask 位。须维持：

- 相同 rank／状态的未来延伸不依赖前缀身份；更优到达替换 `(cost,mask)`，同代价
  OR，不可达为 `(INF,0)`。
- 完整花色表中所有 `cost<=d` 的 `(sets,pair)` 表项精确保留代价及全部最优 mask；
  截断表返回前把超界结果归一为 `(INF,0)`，不留部分搜索产生的有限但不精确结果。
- 跨花色面子／将牌分配不变；标准型与七对并列时 OR，七对不改，标准型被截去不得
  判断整手不可达。
- 完整缓存可服务有界查询；截断表不得污染完整缓存或冒充更宽 cutoff 的结果，有界
  整手结果只有证明已是完整 `(D,M)` 才可复用。

## 3. 阶段一：只归因工作量

先不改生产行为。以真实 `heuristic-benchmark-v1` 请求流临时插桩，每 seed 2000 局、
warmup 20、seed 7／10007，预热不计入统计；研究侧影子执行不得回答生产查询或改变
生产缓存。统计整手与花色表的请求／命中／未命中／实际构建、每 rank 的活跃状态、
扩展和合法转移，以及基线 `g>d` 状态数与 `g+Δ>d` 转移数。令 `N_0`／`N_d` 为未截断／
截断执行的合法转移枚举数，`ρ=(N_0-N_d)/N_0`；`N_d` 必须来自实际执行。按 seed、
deficit、副露 0–4、缺门／非缺门报告计数与按总和计算的 `ρ`；核内配对真实基线构建，
另报请求流级净变化。**先交付分布及进入／不实施判断，不预设 `ρ` 门槛；插桩耗时
不能作性能结论。**

## 4. 阶段二：最小候选

仅有工作量依据时实施简单 `g>d` cutoff，检查后继时同样只拒绝严格大于 `d`。接线为
`rank_discards → 精确候选 deficit → ukeire → deficit_with_mask → suit_table_masked`，
传入已有距离，不为 cutoff 重算。碰后弃牌及不碰响应、明／暗／补杠等 `ukeire()` 入口
须保证手牌／上下文一致；其他完整 `deficit_with_mask()` 调用保持原语义。截断缓存如
存在须区分覆盖范围，或不缓存并把重建成本计入实验；普通距离与 Surplus 保持原成本
边界。

## 5. 阶段三：正确性

复用 [`one_pass_tests/oracle.rs`](../../../src/policy/analysis/one_pass_tests/oracle.rs)
的独立 concrete-target 枚举及既有完整花色表、排序、碰杠与续局测试，不用候选 DP
自证：比较原 DP、候选和 oracle 的完整全局 `(deficit,mask)`，所有 `cost<=d` 表项
精确保留且与 oracle 一致。覆盖标准型、七对及并列、多最优目标、跨花色分配、三种
缺门、0–4 副露、碰／各类杠容量、`d=0`、`g=d` 零代价完成、超界与不可达；覆盖缓存

## 6. 阶段四：性能验收

固定 B/C 源码、工具链、依赖、默认 Release 配置及环境，分别构建并保存无研究插桩
二进制；正式运行直接调用保存镜像：

```sh
cargo build --release --locked --example heuristic_bench
<saved-binary> --games 2000 --seed 7 --warmup 20
<saved-binary> --games 2000 --seed 10007 --warmup 20
```

遵守 `heuristic-benchmark-v1` 的种子和阶段隔离。计时沿用 `BatchReport.total_time`
（含建局，不含进程启动和预热），另报 `policy_time`／`rules_time`。每 seed 先
**3 对 B/B**，再 **5 对 B/C**，顺序 `BC、CB、BC、CB、BC`；各按轮先 seed 7 再
10007。全部串行，不与构建、测试、trace、采样或计数重叠；预先固定异常处理，不按
结果剔除、替换或追加样本。

**采用门槛：** 正确性通过且两个 seed 分别同时满足 (1) 至少 4/5 对端到端
`total_time` 改善；(2) 配对降幅 `1-C/B` 中位数严格超过该 seed 三对 B/B 的
`max(|1-B_second/B_first|)`。不设 2% 下限；策略时间须报告但不设门槛；不用两侧独立
中位数相除代替配对统计；转移减少比例或微基准不能当作端到端加速比。

## 7. 后续与退出

仅当简单 cutoff 显示潜力时，可独立研究 `g+L(X)>d`：先证明 `L` 对所有适用状态／
目标分配都是未来补牌代价下界，再单独比较，不与简单 cutoff 捆绑。潜力低、判断／
缓存成本抵消节省、精确性失败、收益未超过噪声或环境无法支持可信测量时停止，不保留
未经验证的生产候选；保留有长期价值的测试与总结，移除无用生产代码和临时插桩。
