# Heuristic Benchmark Baseline — Specification

## 目标与范围

提供一个独立、可重复的四席 `HeuristicPolicy` 端到端性能测量入口，
用于观察真实批量自对弈的吞吐量与策略决策成本。
[设计文档](design.md)解释取舍；本文定义本 Change 的预期行为与验收条件，
不代表功能已经实现或已经取得性能结果。

新增 Cargo example `examples/heuristic_bench.rs`，不改变主模拟 CLI。
复用 `Runner::run_batch` 驱动完整游戏，不另建游戏驱动逻辑，
不修改 `Game`、`Policy`、`Runner` 的对外契约、游戏规则或策略选择逻辑。

## 命令行与输入

测量命令的形式为：

```text
cargo run --release --example heuristic_bench -- --games N --seed S --warmup W
```

三个参数均须显式指定，没有默认工作负载：

| 参数 | 含义与取值 |
| --- | --- |
| `--games N` | 正式测量局数，`u64`，且 `N > 0` |
| `--seed S` | 正式测量的首个游戏种子，`u64` |
| `--warmup W` | 预热局数，`u64`，允许为 `0` |

上述数字使用十进制无符号整数。缺少必需参数、缺值、格式错误、
超出取值范围、未知参数或不满足种子区间约束，均须在运行游戏前拒绝，
给出错误说明并以非零状态退出。`-h` / `--help` 可在不提供测量参数时
打印用法并成功退出，不运行游戏。

每局沿用现有 `Runner` 的默认决策上限（当前为 `10_000`），
不增加决策上限选项。该上限按每局计数，而非整个批次累计；
报告须标明实际采用的值，并与公开的
`sichuan_mahjong_sim::runner::DEFAULT_DECISION_LIMIT` 保持一致，
不得另用可能与实际配置脱节的字面量。

## 工作负载协议

本文定义的初始协议标识为 `heuristic-benchmark-v1`。
一次正常调用只包含一次预热阶段和一次正式测量阶段，不自动重复或汇总多次测量。
两阶段在同一进程、同一线程内依次执行，四席均使用独立的 `HeuristicPolicy` 实例，
不共享玩家私有信息。

### 种子区间

所有种子运算按模 `2^64` 解释：

- 正式游戏 `i` 使用 `S.wrapping_add(i)`，`0 <= i < N`。
- 预热起始种子为 `S.wrapping_sub(W)`；预热游戏 `j` 使用该起点
  `wrapping_add(j)`，`0 <= j < W`。
- 两个区间在环上相邻且不得重叠。因此，必须满足数学整数意义上的
  `N + W <= 2^64`；校验不得因 `u64` 加法溢出而失效。
- 修改 `W` 不得改变正式种子序列。不同种子不构成不同牌局内容的保证。

例如，`S = 0, W = 2, N = 2` 时，预热使用
`[u64::MAX - 1, u64::MAX]`，正式测量使用 `[0, 1]`。
`S = u64::MAX, N = 2` 时，正式测量使用 `[u64::MAX, 0]`。

### 阶段与实例生命周期

1. 完成输入校验。
2. 若 `W > 0`，新建一个 `Runner` 及其四席策略，执行一个 `W` 局的预热批次。
   该批次内复用同一组策略实例，所有游戏均须运行至终局。
3. 预热完成后丢弃该阶段的 `Runner`、策略和报告。
   若 `W = 0`，直接跳过预热，不调用 `run_batch(_, 0)`。
4. 新建正式 `Runner` 及其四席策略，以 `S` 为起点执行一个 `N` 局批次。
   正式批次内复用同一组策略实例，不逐局重建，不按已用时间调整局数。
5. 仅在所需阶段全部成功后输出正式结果。

预热游戏的计数、耗时、得分、胜局数和终局类型均不得混入正式报告。
`W = 0` 表示禁用预热，输出须能识别这一配置，不能将其描述为已执行预热。

阶段隔离不承诺清空分配器、CPU 缓存或其他进程级状态；
本协议不是冷缓存协议，也不要求缓存重置接口。
当前 `HeuristicPolicy` 的分析缓存限于单次 `choose` 调用，
预热不意味着正式阶段继承了策略实例中的热缓存。

## 计时与报告

### 计时含义

直接采用正式 `run_batch` 的计时结果，不用外层进程耗时替代批次耗时：

- `total_time`：正式批次的整体墙钟时间，覆盖游戏构造、驱动、聚合及其间开销。
- `policy_time`：正式批次所有 `Policy::choose` 调用的累计耗时。
- `rules_time`：正式批次 `Game::next_decision` 与 `Game::submit` 的累计耗时。

输入解析、预热、正式 `Runner` 与策略的构造、最终输出均不属于正式计时窗口。
保留现有逐决策计时，不增加逐决策输出、trace 收集或额外 profiling。
分段耗时不是整体耗时的精确分解，不要求两者之和等于整体耗时。

### 最小输出语义

输出采用易读的纯文本，至少包含：

| 内容 | 要求 |
| --- | --- |
| 工作负载配置 | 协议标识、四席策略名称、`S`、`N`、`W`、实际每局决策上限 |
| 正式完成量 | 完成局数、总决策数 |
| 耗时 | `total_time`、`policy_time`、`rules_time` |
| 主要性能观察 | 游戏吞吐量，即正式完成局数 / `total_time` 秒数，单位 games/s |
| 策略决策成本 | 平均策略耗时，即 `policy_time` / 正式总决策数，包含所有类型的策略调用 |
| 游戏结果 | 按座位的累计净分、按座位的胜局数、三人获胜终局数、牌墙耗尽终局数 |

时间字段必须注明单位；座位数组必须注明或清楚表达固定的座位顺序。
平均策略耗时不是复杂出牌分析的独立延迟，不能只取某一类决策作分母。
零决策时平均策略耗时须标为不可用；零耗时时吞吐量须有保护，
不得因除零输出无穷值或 `NaN`。

字段含义与单位在同一协议内保持稳定，但不冻结文本布局为永久公共数据格式。
改变种子、实例生命周期或计时边界等测量语义时，必须明确区分协议，
不能把不兼容结果继续标为同一协议。

这些非时间聚合字段用于诊断工作负载差异，不是逐动作行为等价的证明。
工具不要求自动采集版本或机器元数据；性能研究仍须自行记录源码版本、
构建方式、工具链、机器环境、完整调用参数和重复运行条件。

## 失败语义

输入错误、预热失败、正式批次失败或结果输出失败，均以非零状态退出，
不得宣称取得有效测量。运行错误须区分预热阶段与正式阶段，并保留底层错误说明。

非法动作、决策上限耗尽、缺失终局结果及其他驱动失败均使整次测量无效。
不得替换动作、跳过失败游戏、把未完成游戏计为零分、自动续跑，
或将已完成的部分批次作为正常测量汇总。
运行失败时不输出正常性能摘要；输出本身失败时，可能残留的部分文本不构成有效报告。

接受现有 `run_batch` 错误不携带失败局种子或局序号的局限；
不为精确定位失败局扩展生产接口，也不增加自动重放定位。

## 验收条件

实现与验证至少应区分以下情形：

- 帮助可独立使用；缺少参数、非法数字、`N = 0`、超范围值及未知参数在运行前失败。
- 种子计划覆盖普通区间、向前和向后环绕，以及 `W = 0`。
  改变 `W` 不改变正式种子序列；相邻区间不重叠。
- 区间校验拒绝 `N + W > 2^64`，接受等于 `2^64` 的边界。
  巨大计数边界只验证配置和种子计算，不要求实际运行相应局数。
- 预热和正式阶段使用不同的 `Runner` 与策略实例，批内实例持续复用；
  零预热不触发空批次错误，预热聚合结果不进入正式报告。
- 同一构建、同一配置的重复运行，其非时间性结果一致。
  对当前确定性策略，改变预热局数也不改变相同正式种子范围的非时间性结果。
- 小规模正式批次确实完成 `N` 局，终局数量之和为 `N`，各席累计净分之和为零；
  输出包含约定的最小字段，平均策略耗时和吞吐量的计算及单位正确。
- 输入错误、预热失败、正式批次失败和输出失败均不会被报告为成功测量；
  相关错误传播可用局部测试夹具验证，不为测试引入新的生产接口。
  新增的自动化测试须能被项目测试命令发现并执行，而非只有未运行的夹具。
- 使用 release 构建完成一个小规模端到端冒烟运行；在
  [README](../../../README.md) 中给出可复现命令、计时边界和测量解释限制，
  并在[当前架构](../../../docs/architecture/overview.md)中反映已实现入口及测试位置。
  测试不要求精确耗时，也不要求预热后一定更快。
- 通过[项目治理](../../../docs/governance.md)规定的标准检查。
  本次若仅修改规格文档，则执行文档链接、范围和 diff 检查，不以此声称实现已通过验收。

## 非目标与完成边界

不包括性能优化、策略强度实验、固定 `Decision` 语料重放、函数级归因、
生产缓存、profiling 框架、结果持久化、自动对比、统计汇总、并行运行或实验编排。
不要求复现、迁移或继续 `feat/heuristic-profiling` 的历史实验，
不同预热协议的数据不得不加区分地混合。

完成以正确执行上述工作负载、准确报告和正确处理失败为准，
不设吞吐量、加速比或策略强度数值门槛。
入口形式及参数提供方式已明确；本规格不把后续研究选择作为实现前置条件。
