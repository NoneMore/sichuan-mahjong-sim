# One-pass Discard — 规格

## 1. 目标与范围

基于主线 `a243b2f658754a26c6332a3a602ae12f884a3b03`，保留 B、A2 和 One-pass Ukeire，实验**通过原始手牌的一次最优目标分析，计算所有候选弃牌的精确 deficit**。这是拟实现契约，不表示实现或验收完成。

动机见[成本归因复测](../../../docs/studies/heuristic-cost-attribution-refresh.md)：`suit_table` / `suit_table_with_mask` 的历史 CPU self 占比为 48.70% / 35.23%，不代表本次性能基线或预期收益。

生产改动限于 [`analysis.rs`](../../../src/policy/analysis.rs) 的必要分析，以及 [`heuristic.rs`](../../../src/policy/heuristic.rs) 中 `rank_discards()` 的候选 deficit 计算：

- 保持候选来源、顺序、无效候选跳过与空结果处理；保持回合和碰后弃牌、碰杠门控、番数裁决及所有既有短路。
- 仍仅对最低 deficit 候选计算 ukeire，沿用弃牌后公开归属与可得张数；完全并列时仍按原候选顺序选择。
- 缓存生命周期及副露/缺门/容量上下文隔离不变，不引入跨决策或跨局缓存；普通 deficit 调用不承担新增 surplus mask 的计算或存储成本。
- 不改变规则、信息边界、合法性、输入支持域与防御性处理，不顺带重构或建设通用实验框架。

遵循[项目治理](../../../docs/governance.md)与[固定规则](../../../docs/baseline-rules.md)；规格原地修订，行为、范围与验收条件同步更新。

## 2. 精确行为合同

上下文 `C` 固定自家副露、缺门与容量，合法目标集合为 `T_C`。原始手牌 `H` 在生产排序入口有 `14 - 3m` 张，`m` 为副露数。新分析返回精确 deficit 与 surplus mask：

```text
D_C(H) = min_{T in T_C} sum_t max(0, T[t] - H[t])
surplus(t) iff 存在达到 D_C(H) 的目标 T，使 T[t] < H[t]

对每张可移除的候选牌 t：
D_C(H - t) = D_C(H)       若 surplus(t)
             D_C(H) + 1  否则
```

目标沿用现有定义：标准型为剩余面子加一对；七对仅无副露时允许，目标计数为 0/2/4，四张算两对。目标暗手共 `14 - 3m` 张，不含缺门，与自家副露合计每牌种不超过四张。他家公开牌只影响 ukeire，不改变结构目标容量。

- **合并所有最低代价目标的 surplus，并非取交集。** 更优代价替换 mask，同代价合并，更高代价及不可达状态不贡献；适用于花色内、跨花色、标准型内部及标准型与七对之间的并列。
- **surplus mask 不是现有 Ukeire needed mask 的取反。** 缺门手牌也可能属于 surplus。
- “一次分析”指一次原始手牌级分析，允许内部花色 DP 与牌型组合；生产路径不得再逐候选独立求解 deficit，测试参考与调试一致性校验除外。

## 3. 正确性验收

在测试中保留旧版“逐候选移除一张，再调用普通 deficit”的参考路径，不得转调新 surplus 分析。优先复用现有测试设施，不复制整个策略。

**逐候选比较精确 deficit，而非仅比较最终弃牌。** 使用明确预期 surplus 的定向用例，以及固定 seed 的随机合法状态，覆盖：

| 类别 | 代表性边界 |
| --- | --- |
| 标准型与并列 | 顺子、刻子、对子竞争；不同最优目标贡献不同 surplus |
| 七对与跨牌型并列 | 奇偶变化、四张算两对、补对子单位；与标准型同代价且贡献不同 surplus |
| 副露与容量 | 0–4 副露；碰后容量 1、杠后容量 0 |
| 缺门与距离 | 三种缺门、未清/已清；原手牌 deficit 为 0、弃牌后听牌及较远距离 |
| 候选与缓存 | 单候选、子集、重排、完全并列；冷热缓存、填充顺序及上下文隔离 |

随机状态须满足手牌、副露与物理牌数一致，记录生成方法、seed、样本量及可复现反例；不要求穷举。

排序层比较候选 deficit、进入 ukeire 阶段候选的 ukeire、最终弃牌与 `Progress`、适用的番数裁决及碰杠决策。对相同固定 seeds 的完整对局，逐动作比较轨迹，并精确比较得分、胜者、决策数与终局原因；批次聚合不能替代逐动作差分。保留合法动作、确定性回放与 clone 后换新策略冷缓存续局回归。

须通过：

```text
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
```

## 4. 性能验证

正确性通过后再进行性能验收，记录基线与候选的具体提交、构建及环境。

- **工作量：**统计 `rank_discards()` 次数与候选数量分布、手牌级分析次数、实际花色 DP 构建次数，以及相关缓存的请求/命中/未命中和命中率；区分普通距离、新 surplus 与现有 Ukeire mask 路径。
- **解释节省：**旧实现在同次排序中已能跨候选复用未变花色的缓存，不能按候选数推算完整 DP 次数。调用次数、构建次数与实际耗时必须区分。
- **受控 A/B：**相同 Release 配置、工具链、flags、环境、seeds、局数、预热与计时边界；多轮串行交错 A/B、B/A，不与构建、测试、采样或 trace 采集并发。
- **工作负载：**优先复用 [`heuristic_bench`](../../../examples/heuristic_bench.rs)，可沿用 2,000 局、预热 20 局、seed 7 和 10007。正式比较前固定参数、重复次数与顺序；调整须两侧同步，不按候选结果挑选配置。
- **结果：**报告端到端批次/策略耗时、配对差值与波动、纯距离候选生成路径的实际成本和工作量变化。新 surplus 成本必须计入该路径；若采样，须区分各路径，不能只看 self 占比。

计数插桩与正式计时隔离，或明确证明两侧计时条件等价。历史占比、调用减少或微基准变快均不能替代端到端结论。

## 5. 去留与交付

先完成可验证的最小候选实现。**只有正确性通过，且重复交错测量显示端到端收益可复现并超出波动，才保留生产优化。** 任意行为差异、持平、退化或无法区分噪声的结果均不达标。

不达标时恢复原生产路径，不遗留未启用的生产实验分支或无用插桩；保留仍有价值的必要回归测试，简记原因。

交付限于必要代码修改（达标才保留）、差分测试、含复现参数与计数口径的性能对比，以及明确的保留/回滚结论。**不需要数学证明、`proof.md`、大规模实验框架或冗长文档。**
