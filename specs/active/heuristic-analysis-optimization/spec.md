# Heuristic Hand Analysis Optimization — Specification

## 目标与性质

本 Change 优化 `src/policy/analysis.rs` 的精确手牌分析，减少启发式策略的计算成本，
不改变规则或策略行为。本文定义拟实施工作与验收契约，不表示优化已经实现或取得收益。

[既有成本归因](../../../docs/studies/heuristic-cost-attribution.md)支持优先关注
`suit_table`，但其中的采样占比是历史观测，不能换算为本 Change 的加速比。
实现前以明确版本的当前代码建立比较基线。

本 Change 遵循[项目治理](../../../docs/governance.md)，不新增独立治理或审批流程。

## 不变的行为契约

令 `m` 为已声明面子数量（包括碰和各类杠），目标暗牌数量为 `14 - 3m`。
精确目标缺口仍为：

```text
D(H) = min over legal targets T of sum_t max(0, T[t] - H[t])
S(H) = D(H) - 1  （H 为 13 - 3m 张的弃牌后手牌）
```

合法目标不含缺门牌，与自家副露合计不超过每种牌四张；标准型目标为
`4 - m` 个面子加一个对子，七对目标仅在没有已声明面子时可用。
手中超出目标需要的牌免费舍弃。缺口为零只有在目标和输入尺寸相等且满足合法副露等
调用前提时才能解释为输入本身和牌，不得将其推广到任意张数输入。

优化必须保持：

- 标准型、七对的 `D(H)`，以及适用输入上的向听数和 `ukeire`；
- 弃牌排序、碰杠选择、番数决胜与最终选择的动作；
- 缺门限制、自家副露四副本容量、公开已见牌与未见牌的计数语义；
- 仅使用玩家可见决策信息的边界、合法动作和固定种子的决策序列；
- 缓存仅为可丢弃记忆化：填充顺序、冷暖状态不影响结果，使用新策略实例的克隆续局
  与原状态续局一致。

[基线规则](../../../docs/baseline-rules.md)不变。不通过调整期望动作、距离或受入值
来接受优化造成的差异。

## 候选范围

### A. 收紧标准型状态转移枚举（主线）

保留已在循环边界内表达的面子预算约束，将仍在枚举后检查的每档容量与
`pair_used` 冲突约束改为更紧的循环边界；容量预算需扣除状态中已有顺子尾巴的
必付张数 `a + b`，不足时可提前跳过该状态。避免枚举必然被现有检查拒绝的组合，
合法转移集合必须保持不变。

在隔离测试或实验中记录代表性输入的候选枚举次数，确认确实减少空转，
而不是只改写已有预算边界。至少包含容量全四、`target_sets = 4` 的配置；
计数下降仅证明工作量减少，不能替代墙钟测量。

结果仍是完整的 `SuitTable[sets][pair_used]`，而不是只计算某个终态。
不能按“本花色必须补齐全部 `target_sets` 个面子或一个对子”剪枝：
调用方需要跨花色组合所有相关条目，其他花色可能提供剩余面子或对子。

本轮不扩展到状态图预计算、转移图缓存或缓冲区机制重构。

### B. 七对 DP 公式化（主线）

仅在现有无已声明面子门控下，用下列精确公式替换七对 DP：

```text
P = sum_t floor(H[t] / 2)  （已有对子单元数，四张同牌贡献两个）
O = sum_t (H[t] mod 2)     （奇数张牌种数，包含持有三张的牌种）
K = max(0, 7 - P)
D_7 = K + max(0, K - O)
```

求和仅含非缺门牌。无已声明面子时，这些牌种的目标容量均为四张：
已有对子单元免费，奇数张牌种各能用一张补出一个额外对子，其余单元各需两张。

任何已声明面子（包括暗杠）仍禁用七对路线。整数计算不得因 `P > 7` 下溢。
同步修订局部注释，区分标准型 DP 与七对公式；不改变目标缺口或缓存的语义。

### C. 跳过缺门花色（主线）

在标准型计算中跳过缺门花色的切片、建表、缓存访问与合并。
缺门容量恒为零，其结果表是花色合并的单位元：

```text
table[0][0] = 0
其他条目 = INF
```

不能用全零表代替。跳过不改变总面子预算或恰好一个对子的要求。
原算法将手中缺门牌视为目标之外的多余牌；即使输入包含缺门牌，本改动也必须保持
原缺口结果，而不是顺带修改强制清缺门策略或增加清缺门代价。

### D. 简化 ukeire 的重复和牌检查（条件性实验）

尝试删除 `ukeire` 中重复的直接和牌分支，由
`D(H + t) < D(H)` 统一识别改善进张。不预先承诺保留该改动。

需明确并验证现有调用前提：

- 输入 `H` 为 `13 - 3m` 张，传入缺口来自同一 evaluator 对该 `H` 的计算；
- evaluator 的副露合法，手牌、自家副露和假设摸牌满足四副本约束；
- `public` 包含自家副露，未见牌过滤保留原语义。

在这些前提下，摸牌后输入与目标尺寸相等，需验证两套实现的一致性：

```text
rules::can_hu(H + t, melds, missing) == (D(H + t) == 0)
```

合法和牌的摸牌后手牌本身就是目标，故其缺口为零，而弃牌后缺口至少为一。
删除分支不应改变受入计数，但会让原本短路的和牌进张进入缺口计算。
需单独评估该成本交换，覆盖听牌、多面听、七对和副露等待场景。
局部测试或观测不能替代端到端测量。

`max_discard_fan` 中用途不同的和牌合法性检查不在删除范围内。

## 验证契约

### 局部等价性

各候选随附测试，不将测试推迟为最终统一补齐项：

| 候选 | 最低覆盖 |
| --- | --- |
| A | 比较完整表的所有条目；覆盖 `target_sets = 0..4`、零容量、碰杠占用容量、顺子起止及尾部边界；参考算法不能复用被验证的新循环边界 |
| B | 与独立七对目标枚举比较；覆盖十八种非缺门牌、总张数不超过十四的全部计数类别（按持有 0/1/2/3/4 张的牌种数量分类，共 241 类）；另覆盖四张两对、三张补对、副露禁用、缺门过滤和整数减法边界 |
| C | 验证零容量表是合并单位元；遍历三种缺门选择；包括非零缺门手牌计数，结果与包含缺门花色的参考计算一致 |
| D | 与原和牌短路逻辑做受入差分，并显式验证上述和牌/零缺口等价；覆盖 `m = 0..4`、标准型及七对、等待与非等待摸牌、自家杠耗尽和公开耗尽；保留直接和牌计入受入的断言 |

参考算法只用于测试或隔离实验，不为对照在生产路径永久保留双实现。

### 集成行为

- 在实现前确定并记录固定种子的行为对照语料，列出完整种子集合或范围、局数和
  采集命令；保存基线来源与可重建的比较材料，不能仅在候选版本中自我重放。
- 通过现有 `Runner::run_new` / `run_game` 采集基线与候选的逐动作 trace，
  并比较决策数、得分、胜者和终局原因等非时间结果。跨局按相同方式复用 Runner。
  现有 `run_batch` 不收集 trace，不能将批量结果或空 trace 相等作为逐动作对照。
- 比较材料可为逐局完整动作序列，或记录序列化规则与算法的逐局摘要；必须检查
  trace 非空且长度与决策数一致，并可按记录的版本、语料与命令重新生成。
- 对同一 evaluator 的重复调用及不同缓存填充顺序，与每次新建 evaluator 的
  `deficit` / `ukeire` 结果逐值比较；另验证克隆游戏后使用新策略实例续局的一致性。
- 正确性对照与性能批量运行分开执行，不在性能测量中加入 trace 收集。
- 局部等价测试和逐动作对照相互补充。终局聚合一致、仅比较测试数量，
  或候选版本自身可重放，都不能单独证明改前改后行为一致。

通过项目标准检查，并增加 release 验证：

```text
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
cargo test --release --all-targets
```

### 性能协议与预算

复用[现有基准](../../../examples/heuristic_bench.rs)的 `heuristic-benchmark-v1`，
保持四席策略、种子序列、实例生命周期和计时边界不变，不新建游戏驱动器。

每个基线—候选比较使用相同的默认 release 构建条件及以下负载：

```text
heuristic_bench --games 2000 --seed 7 --warmup 20
heuristic_bench --games 2000 --seed 10007 --warmup 20
```

具体执行规则：

1. 每组种子先运行三对。一对为相同配置下基线和候选各运行一次；交替两者先后顺序。
   两组种子采用相反的首对顺序，追加阶段接续交替，不因首轮结果重排次序。
2. 若结论不确定且影响保留决定，每组追加两对，合计上限为每组五对。
3. 追加后以全部五对结果重新判定，不能只选择有利样本或只报告追加阶段。
4. 达到预算仍无法区分时，记录为“不确定”并停止，不自动增加局数或重复次数。
5. 测量串行执行，不与构建、测试或其他基准重叠。失败运行不能作为正常测量；
   不得静默丢弃失败或不利样本，需要重启实验时须记录原因并另行决定，不自动突破预算。

记录可重建的源码版本或补丁、构建方式、工具链、机器环境、完整参数、运行次序与
逐次结果。使用相同条件保存的基线和候选产物，不用历史报告中的耗时替代本次基线。

以正式批次 `total_time` 判定端到端效果，同时报告 `policy_time`、吞吐量、
逐对变化、中位数和范围，解释局部收益与整体效果。不得以外层进程耗时替代
批次计时，也不得用迭代次数、采样权重或局部微基准代替端到端收益。

### 保守工程判据

对同一比较的每组种子分别计算基线和候选 `total_time` 的最小—最大范围：

- 两组都满足“候选最大耗时 < 基线最小耗时”：**可辨识收益**；
- 两组都满足“基线最大耗时 < 候选最小耗时”：**可辨识回退**；
- 其余情况，包括范围重叠、边界相等或种子之间方向不同：**不确定**。

这是保守的工程判据，不是统计显著性声明。“不确定”不等于证明性能相同或无回退。
小幅效应可能无法在本预算下辨识，特别是 B、C；这本身不是正确性失败，
也不是突破预算以追求确定结论的理由，按下文简化收益原则处理。

测量需区分：

- A、B、C 各单项相对原基线的效果；
- 拟保留主线组合相对原基线的效果；
- D 相对拟保留主线组合的增量效果；
- 如果保留 D，最终组合相对原基线的效果。

若组合与某个单项完全相同，可引用同一比较结果，无需重复相同实验。
D 的组合测量有真实的实验依赖，但四项在实现语义上可独立验证；
不能用组合提速掩盖 D 或其他单项的已知回退。

## 保留与完成条件

前三项作为主线实施与验证，不等于无条件全部合入。逐项及最终组合按下列原则处理：

| 结果 | 处理 |
| --- | --- |
| 行为不一致 | 不接受，先定位并修正；不得通过修改既定行为期望放行 |
| 可辨识回退 | 不按当前形式保留 |
| 正确且可辨识收益 | 可以保留 |
| 正确、结果不确定且明显简化实现 | 可以保留，但须记录简化理由、未证实提速及剩余不确定性 |
| 正确、结果不确定且主要为提速而增加复杂度 | 暂不保留 |

D 同样遵循这些标准，并须独立通过调用契约、等价性和成本交换评估。
“可以保留”不是自动合入承诺；实现与结果报告需说明实际选择及理由。

本 Change 的完成产出包括：

- 各候选的等价实现与测试，或其不保留的结论及足以复核的版本/差异；
- 基线、单项与组合的行为对照和有界性能测量记录；
- 每项保留或撤回的理由，以及最终组合的验证结果；
- 与最终实现一致的局部不变量、调用前提和算法注释。

不设固定加速百分比，不要求四项全部保留，不为得到确定结论无限追加测量。
如果主线候选均不满足保留条件，可以用完整的负面或有界未决结论结束，
不得将被撤回候选描述为已实现收益。

## 非目标与文档边界

不包括规则或策略强度调整、跨决策缓存、缓存键重设计、状态图预计算、公开分析接口、
生产埋点、通用 profiling/benchmark 框架或新的实验驱动入口。
允许为本 Change 使用最小隔离测试与实验脚本，包括通过现有 Runner API 进行
一次性 trace 采集和跨版本比较，但不另写游戏推进逻辑或扩大为长期基础设施建设。

本规格提交是文档工作，不代表上述实现、回归或性能验收已经通过。
实现后按实际影响更新文档；不对未改变的规则、公共 API 或架构开展无关文档扫改，
不因局部等价优化新增 ADR。
