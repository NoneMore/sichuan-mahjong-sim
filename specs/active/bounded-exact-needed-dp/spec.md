# Bounded Exact Needed-mask DP

研究能否用已知精确最优距离减少 `suit_table_masked` 的状态扩展和转移，并提高启发式策略端到端效率。**这是允许停止或回滚的实验，不要求留下优化。** 先证明正确，再测计算量，最后验证真实速度；转移减少不等于加速。

遵循[项目治理](../../../docs/governance.md)，规格原地修订，结束后按约定归档。当前只完成规格，尚无本任务的实验结果。

## 2. 精确性合同

上下文 `C` 固定副露、缺门及物理容量，沿用现有合法目标集合 `T_C`：

\[
D_C(H)=\min_{T\in T_C}\sum_t\max(0,T_t-H_t),\qquad
M_C(H)=\bigcup_{T:\,cost_H(T)=D_C(H)}\{t:T_t>H_t\}.
\]

`M` 是全部最优目标的 Needed-mask 并集，公开耗尽的牌种仍可有结构位，但 ukeire 贡献为零。

已知同一 `(H,C)` 的精确有限值 `d=D_C(H)`。所有转移新增代价非负，因此累计代价 **`g > d`** 的路径不可能属于全局最优目标；不能剪掉 `g=d`，它仍可能零代价完成并贡献独有 mask 位。实现前须论证以下不变量：

- 相同 rank／状态的未来延伸不依赖前缀身份；更优到达替换 `(cost,mask)`，同代价 OR，不可达为 `(INF,0)`。
- 全手最优目标各花色代价均不超过 `d`。完整花色表中所有 `cost <= d` 的 `(sets,pair)` 表项必须精确保留代价及全部最优 mask；新建截断表返回前将超界结果归一为 `(INF,0)`，不能留下部分搜索产生的有限但不精确结果。
- 跨花色面子／将牌分配不变；标准型与七对并列时 OR。七对不改；若标准型距离大于全手 `d`，允许该路线被截去，不能因此判整手不可达。
- 截断不代表一般查询下无效。完整缓存可服务有界查询；截断花色表不得污染完整缓存或冒充更宽 cutoff 的结果。有界整手结果如要复用，须证明已是完整全局 `(D,M)`。

## 3. 第一阶段：只归因工作量

先不改生产行为。以真实 `heuristic-benchmark-v1` 请求流临时插桩，使用 2000 局、warmup 20、seed 7／10007；预热不计入正式统计，不跨 evaluator 合并缓存键。允许研究侧影子执行 cutoff，但不得用其结果回答生产查询或改变生产缓存。

分别统计整手 Needed 查询和花色表的请求、命中、未命中、实际构建，以及：

- 每个 rank 实际访问的有限活跃状态、实际扩展状态、通过原容量／面子／将牌约束的合法转移。
- 基线中 `g>d` 的状态数与 `g+Δ>d` 的合法转移数。
- 真正剪枝后避免的状态访问、扩展和转移；严格更优写入、同代价到达、mask OR 次数及实际增加位的次数。同代价到达不是不同全手最优目标的总数。

令 `N_0`／`N_d` 为对应未截断／截断执行的合法转移枚举数：

\[
\rho=(N_0-N_d)/N_0.
\]

`N_d` 必须来自实际研究侧执行，不能拿超界转移数代替。已经枚举才被 cutoff 拒绝的转移本身不算省掉；后继可能经其他较便宜前驱到达，不能重复计节省。

按每个 seed、deficit、0–4 副露、缺门／非缺门花色报告原始计数和比例，再按计数之和计算总比例；不平均各桶百分比，零分母标不适用。核内比较配对真实基线构建的相同输入／容量／面子预算／cutoff；若候选缓存会增加构建，另报请求流级净变化，不能把核内潜力冒充净收益。

**先交付实际分布及“进入候选／不实施”的判断。** 不预设 `ρ` 门槛；潜力低可停止，插桩耗时不能作性能结论。

## 4. 第二阶段：最小候选

仅有工作量依据时实施简单 `g>d` cutoff；检查后继时也必须严格大于 `d`。记录检查位置、缓存隔离和不可达处理决定，并满足第 2 节合同。

真实接线为 `rank_discards → One-pass Discard 精确候选 deficit → ukeire → deficit_with_mask → suit_table_masked<false>`。将已有距离传到 Needed DP，不为取得 cutoff 重算距离。碰后弃牌，以及不碰响应、明杠、暗杠、补杠等 `ukeire()` 入口同样保证手牌／上下文一致。

其他要求完整 `deficit_with_mask()` 的调用保持原语义。截断缓存如存在，区分 cutoff 覆盖范围；也可不缓存，但重建成本必须计入实验。普通距离和 Surplus 路径保持原实现与成本边界。

## 5. 第三阶段：正确性

复用 [`one_pass_tests/oracle.rs`](../../../src/policy/analysis/one_pass_tests/oracle.rs) 的独立 concrete-target 枚举及既有完整花色表、排序、碰杠与续局测试，不用候选 DP 自证：

- 覆盖标准型、七对及并列、多最优目标、跨花色分配、三种缺门、0–4 副露、碰／各类杠容量、`d=0`、`g=d` 零代价完成、超界及不可达状态。

## 6. 第四阶段：性能验收

正确性通过后，固定 B/C 源码、工具链、依赖、默认 Release 配置及环境，分别构建并保存无研究插桩二进制；正式运行直接调用保存镜像：

```sh
cargo build --release --locked --example heuristic_bench
<saved-binary> --games 2000 --seed 7 --warmup 20
<saved-binary> --games 2000 --seed 10007 --warmup 20
```

遵守 `heuristic-benchmark-v1` 的种子和阶段隔离。计时沿用 `BatchReport.total_time`（含建局，不含进程启动和预热），另报 `policy_time`／`rules_time`；详细 DP 计数与正式计时分开。

每 seed 先 **3 对 B/B**，再 **5 对 B/C**，顺序 `BC、CB、BC、CB、BC`；校准和比较各按轮先 seed 7 再 10007。全部串行，不与构建、测试、trace、采样或计数重叠。预先固定异常运行处理，不按结果剔除、替换或追加样本；保留每次原始计时、非计时输出、pair 标识、顺序及失败记录。

**采用 Dual-mask 门槛：仅当正确性通过，且两个 seed 分别同时满足以下条件，才保留：**

1. 至少 4/5 对端到端 `total_time` 改善；
2. 配对降幅 `1-C/B` 的中位数，严格超过该 seed 三对 B/B 的 `max(|1-B_second/B_first|)`。

**不设 2% 下限；策略时间须报告，但不另设其通过门槛。** 不用两侧独立中位数相除代替配对统计。B/B 只刻画校准期波动，须报告后续漂移和后台活动等限制。

收益接近噪声时，可另行事前固定长批次方案与判据，区分探索性／确认性实验，不靠追加样本改变原轮判定。微基准、缓存命中或转移减少比例不能直接当作端到端加速比。

## 7. 后续、退出与交付

仅简单 cutoff 的工作量显示潜力时，可独立研究 `g+L(X)>d`：先证明 `L` 对所有适用状态／目标分配都是未来补牌代价下界，不能假设某花色承担全部剩余面子；再实现，单独比较，不与简单 cutoff 捆绑。

工作量潜力低、判断／缓存成本抵消节省、精确性失败、收益未超过噪声或环境无法支持可信测量时，停止并不保留未经验证的生产候选。保留有长期价值的测试与总结，移除无用生产代码和临时插桩。
